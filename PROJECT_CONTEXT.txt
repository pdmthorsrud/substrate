PROJECT CONTEXT: GEMINI COMPUTER USE WITH PLAYWRIGHT BROWSER AUTOMATION

==============================================================================
OVERVIEW
==============================================================================

This is a Docker-based browser automation system that integrates Google's Gemini Computer Use API with Playwright for AI-controlled web browsing. The system runs a Chromium browser inside a Docker container and allows Gemini AI to control it through function calls, creating an autonomous agent that can navigate the web, take screenshots, and perform tasks based on natural language instructions.

==============================================================================
KEY COMPONENTS
==============================================================================

1. DOCKER CONTAINER
   - Based on official Playwright image (mcr.microsoft.com/playwright:v1.48.0-jammy)
   - Includes Chromium browser pre-installed
   - Python 3 environment with all dependencies
   - VNC server support for watching the browser in real-time
   - noVNC for browser-based VNC access at http://localhost:6080

2. GEMINI COMPUTER USE API
   - Uses model: gemini-2.5-computer-use-preview-10-2025
   - Configured for ENVIRONMENT_BROWSER mode
   - Returns function calls that control the browser
   - Receives screenshots and URLs as feedback
   - Operates in a continuous loop until task completion

3. PLAYWRIGHT BROWSER AUTOMATION
   - Chromium browser with viewport 1280x720
   - Can run in headless or headed mode (with VNC)
   - Takes screenshots after each action
   - Executes navigation commands from Gemini

==============================================================================
ARCHITECTURE & WORKFLOW
==============================================================================

CONVERSATION LOOP:
1. User provides initial prompt (e.g., "open nrk.no")
2. Script sends prompt + conversation history to Gemini API
3. Gemini responds with function call (e.g., navigate to URL)
4. Script executes function using Playwright
5. Script takes screenshot and gets current URL
6. Screenshot + URL sent back to Gemini as function response
7. Loop repeats until Gemini returns no more function calls (task complete)

CURRENTLY IMPLEMENTED FUNCTIONS:
- open_web_browser: Navigates to about:blank
- navigate: Navigates to specified URL with 30s timeout

VNC ARCHITECTURE:
Docker Container contains:
  - Xvfb (Virtual X Server on display :99, resolution 1280x720)
  - Playwright Browser (controlled by Gemini AI)
  - x11vnc Server (port 5900)
  - noVNC + websockify (port 6080)
User accesses via web browser at http://localhost:6080 to watch in real-time

==============================================================================
MAIN SCRIPT DETAILS (gemini_computer_use.py)
==============================================================================

KEY FUNCTIONS:

initialize_browser(playwright):
  - Reads HEADLESS environment variable (default: true)
  - Launches Chromium browser with 1280x720 viewport
  - Returns browser and page objects

take_screenshot(page, step_number):
  - Takes full-page screenshot as PNG
  - Saves to /app/screenshots/ with timestamp
  - Returns screenshot bytes and mime type
  - Note: Compression code is commented out but available (JPEG, 512x288, reduces tokens by ~85%)

execute_function_call(function_name, function_args, page):
  - Routes function calls to appropriate handlers
  - Currently handles: open_web_browser, navigate
  - Logs warnings for unimplemented functions

parse_function_call(response):
  - Extracts function call from Gemini response
  - Returns (function_call_part, function_name, function_args)
  - Returns (None, None, None) if no function call found

MAIN EXECUTION LOOP:
1. Initialize Gemini client with API key from environment
2. Configure model with computer_use tool (ENVIRONMENT_BROWSER)
3. Set temperature to 0.0 for deterministic behavior
4. Initialize Playwright browser
5. Start conversation with user's initial prompt
6. Loop up to 50 steps (safety limit):
   - Log conversation history details (text chars, images, tokens estimate)
   - Send entire conversation history to Gemini
   - Parse response for function call
   - If function call exists:
     * Execute function via Playwright
     * Take screenshot
     * Get current URL
     * Add assistant's function call to history
     * Add function response (screenshot + URL) to history
     * Continue loop
   - If no function call:
     * Task is complete, print any text response, break loop
7. Close browser after 2 second wait

CONVERSATION HISTORY FORMAT:
- List of types.Content objects with role "user" or "model"
- Each Content has parts array containing:
  * types.Part(text=...) for text
  * types.Part(function_response=...) for function responses with screenshots
  * function_call parts from Gemini's responses

LOGGING:
- Detailed step-by-step logging with timestamps
- Tracks: step number, conversation size, text characters, image count, estimated tokens
- Shows function calls, arguments, URLs, screenshot info

==============================================================================
TECHNICAL DETAILS
==============================================================================

GEMINI API CONFIGURATION:
- Model: gemini-2.5-computer-use-preview-10-2025
- Tool: types.Tool(computer_use=types.ComputerUse(environment=types.Environment.ENVIRONMENT_BROWSER))
- Temperature: 0.0 (deterministic)
- Conversation history includes:
  * User text prompts
  * Model function calls
  * User function responses with base64-encoded screenshots
- Screenshots sent as: {"mime_type": "image/png", "data": base64_string}
- Function responses include: url (current page URL) and screenshot

PLAYWRIGHT CONFIGURATION:
- Browser: Chromium
- Headless: Controlled by HEADLESS environment variable
- Viewport: 1280x720
- Navigation timeout: 30 seconds
- Wait condition: domcontentloaded
- Screenshot: Full page PNG format

SCREENSHOTS:
- Saved to /app/screenshots/ (mounted to host ./screenshots/)
- Filename format: YYYYMMDD_HHMMSS_step_N.png
- Full resolution: 1280x720 (or page height if taller)
- Format: PNG (uncompressed currently, JPEG compression code available)

SAFETY LIMITS:
- Max steps per task: 50 (prevents infinite loops)
- Navigation timeout: 30 seconds
- Browser close wait: 2 seconds

TOKEN OPTIMIZATION:
- Screenshot compression available but currently disabled
- If enabled: Resize to 512x288, save as JPEG quality 75
- Compression reduces size by ~85% and tokens by ~85%
- Trade-off: Lower resolution might affect Gemini's understanding

==============================================================================
ERROR HANDLING & DEBUGGING
==============================================================================

COMMON ISSUES:

1. "GOOGLE_API_KEY environment variable not set"
   Solution: Create .env file with GOOGLE_API_KEY=your_key

2. "Browser closed" or "Connection refused"
   Solution: Increase shared memory --shm-size=2gb (already in docker-compose.yml)

3. Screenshots not appearing
   Solution: Check directory exists and is mounted (docker-compose volumes)

4. Permission denied on Linux
   Solution: chmod 777 screenshots/

5. Container exits immediately
   Solution: Check logs (docker-compose logs) for errors

6. Token limit error
   Solution: Enable screenshot compression (uncomment lines 75-92 in gemini_computer_use.py)

7. Navigation timeout
   Solution: Increase timeout in execute_navigate function (currently 30000ms)

DEBUGGING COMMANDS:
- Check environment: docker exec playwright-browser env
- Check API key: docker exec playwright-browser printenv GOOGLE_API_KEY
- Check display: docker exec playwright-browser printenv DISPLAY
- List screenshots: docker exec playwright-browser ls -la /app/screenshots
- Check processes: docker exec playwright-browser ps aux
- Interactive shell: docker exec -it playwright-browser /bin/bash
- Python interactive: docker exec -it playwright-browser python3
- View logs: docker-compose logs -f

LOGGING ANALYSIS:

EXTENDING THE SYSTEM
==============================================================================

TO ADD NEW FUNCTIONS:

1. Define function in Gemini API (declaratively via Computer Use tool - it provides functions automatically)
2. Add handler in execute_function_call:
   ```python
   elif function_name == "new_function":
       execute_new_function(page, function_args)
   ```
3. Implement handler:
   ```python
   def execute_new_function(page: Page, args: dict):
       # Extract args
       param = args.get('param')
       # Perform action
       page.some_action(param)
       log(f"Executed new_function with {param}")
   ```

POTENTIAL FUNCTIONS TO ADD:
- click: Click element by selector or coordinates
- type_text: Type into input fields
- scroll: Scroll page up/down
- screenshot_element: Screenshot specific element
- wait_for_element: Wait for element to appear
- extract_text: Extract text from element
- fill_form: Fill form fields
- go_back/go_forward: Browser navigation
- close_tab/new_tab: Tab management
- hover: Hover over element

CURRENT LIMITATIONS:
- Only implements: open_web_browser, navigate
- No element interaction (clicking, typing, scrolling)
- No element extraction or analysis
- No form filling
- No multi-tab support
- No JavaScript execution
- No cookie/session management
- No file uploads/downloads

GEMINI DECIDES:
- Which functions to call
- When to call them
- What arguments to provide
- When task is complete
The system just needs to implement the function handlers.

==============================================================================
KEY INSIGHTS & DESIGN DECISIONS
==============================================================================

WHY DOCKER:
- Consistent environment across platforms (macOS, Linux, Windows)
- Playwright requires specific browser binaries and dependencies
- VNC setup complex, easier in container
- Isolation from host system
- Easy cleanup and reproducibility

WHY VNC:
- Debugging: See what browser is actually doing
- Demonstrations: Show AI controlling browser in real-time
- Education: Understand how Gemini makes decisions
- Trust: Verify actions before deploying headless

WHY CONTINUOUS LOOP:
- Computer Use requires iterative process
- Each action needs feedback (screenshot + URL)
- Agent decides when task is complete
- Mimics human computer interaction pattern

WHY SCREENSHOTS:
- Gemini needs visual feedback to understand current state
- Text alone insufficient for complex web pages
- Screenshots enable visual reasoning
- Critical for Computer Use API functionality

WHY CONVERSATION HISTORY:
- Context needed for multi-step tasks
- Gemini learns from previous actions
- Function responses inform next decisions
- Enables complex task planning

TOKEN CONSIDERATIONS:
- Full resolution screenshots (1280x720 PNG) are large
- Each screenshot ~500KB = ~20,000 tokens estimate
- Conversation history grows with each step
- Compression available but disabled (caused errors in testing)
- Trade-off: Image quality vs. token usage vs. task success

SAFETY LIMITS:
- Max 50 steps prevents infinite loops
- Timeouts prevent hanging
- Logging helps identify issues
- Container isolation limits damage from errors

CONTEXT FOR AI ASSISTANTS
==============================================================================

IF YOU ARE AN AI ASSISTANT READING THIS:

This project is a working prototype of Google Gemini's Computer Use API integrated with Playwright browser automation. The core loop is:
1. Send prompt and conversation history to Gemini
2. Gemini returns function call
3. Execute function with Playwright
4. Take screenshot and get URL
5. Send screenshot + URL back to Gemini
6. Repeat until Gemini says task is done

The system currently only implements basic navigation (open browser, go to URL). The Gemini Computer Use API automatically provides browser control functions, and this code just needs to implement the handlers.

Key files:
- gemini_computer_use.py: Main loop implementation
- docker-compose.yml: Container configuration
- Dockerfile: Image with Playwright + VNC

The conversation history grows with each step and includes base64-encoded screenshots, which consume many tokens. Screenshot compression is available but currently disabled.

The system runs in Docker for consistency and isolation. VNC is available for watching the browser in real-time at http://localhost:6080 when HEADLESS=false.

For extending: Add new function handlers in execute_function_call() and implement the Playwright actions. Gemini will automatically discover and use them.

Main limitations: Only implements navigate/open functions, no element interaction, single browser instance, no production hardening.

This is research/development code, not production-ready. Treat it as a proof-of-concept for AI-controlled browser automation.
